# W2 维持：任务边界与 M1 接口契约

最后更新：2026-10-01。来源 agent-ops-platform@216d302 + 未提交修改；Codex。

电商请求以 request_id、预算、类目、收货区域输入；规划器产生 catalog、pricing、shipping 三个不同角色的任务，任务包含唯一 task_id、依赖 task_id 与类型化输入。分派器按角色注册处理器，不能运行未完成依赖的任务。结果由 recommendation 任务汇总；任何任务失败时保留 task_id、错误码与执行状态，不拼接伪造成功结果。

M1 使用本地确定性规划器与演示工具，验证编排，不依赖线上模型。M2 才通过 agent-memory HTTP SDK 读写；M1 不把业务任务存进 memory 数据库，不跨仓库 import 应用实现。无记忆服务时 M1 仍可独立运行。

验收要观察拆解后的角色、依赖、实际分派顺序与最终推荐，不能只测试规划器返回列表。该契约为 W2 独立维持项，W4 的实现与端到端验证另记。
