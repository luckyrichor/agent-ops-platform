## 纠错而不改写基线

1. 人工路由的英文关键词原先按子串识别，`humanitarian aid` / `inhuman behavior` / `humanoid robot`会误转人工。加英文单词边界，明确的human/fraud/privacy仍转人工。没有加“退掉”等S5语料规则，不拿47条回归当独立路由质量数据。
2. 内部记忆HTTP客户端原先继承终端代理；无效代理甚至会在客户端构造阶段产生500，而不是沿用记忆失败降级。内部客户端显式不继承环境代理；认证、超时和memory409传播契约保持。回归用无效代理环境加mock SDK，不访问网络。
3. 旧measure-streams.py每次创建Dispatcher未关闭，并覆盖固定历史文件。本轮改为共享同一Dispatcher且finally清理，默认输出.local、新路径存在则拒绝覆盖。旧2026-10-02原始结果不修改。
4. 方案S4写“无并发上限”不符代码：LLMPlanner已有Semaphore，默认8、可配置1–64，总预算包含等槽与重试。真正缺少的是入口排队上限、全局额度限制、熔断和隔舱/兜底策略，留后续验证。B0不移除既有限流以制造更差基线。

## 指标与边界

B0先建立单进程、内存工单、本地固定工具、确定性planner的实际HTTP基线，不依赖火山密钥，不把离线数据当真实模型性能；不虚构至少500次真实模型分布（属后续模型桩工作）。没有PG/Redis缓存、真实商品或支付，不能用于宣称百万工单或万级连接能力。

指标脚本：`scripts/benchmark-b0.py`，loopback TCP真实HTTP和SSE消费；固定输入、显式预热、五个新服务进程重复、每轮原始样本、p50/p95/p99、吞吐及服务CPU/RSS。成功必须核对业务结果，不只看HTTP200。预期409单独统计，不当服务器故障。CPU亲和性在Linux按可用核分离发压与API，具体核/组件版本/配置及源码hash写入report.json；同机压测绝对值不当生产容量。

响应体、服务token和用户消息不落入测量日志；只有固定案例名、状态码、耗时、trace一致性和汇总。服务仍无客户身份隔离，只绑定127.0.0.1。B0只是以后对照点，不预先规定提升比例，不宣称优化收益。
