# P8 路由评测方案（待确认，未实施评测）

2026-10-29。依据主方案 §6 P8、§4/§5 的2000条、70/30划分和负责人本轮补充。P7已验收；本轮仅补P7权限/样本，另准备独立DeepSeek传输层及离线测试。未生成正式评测集、未修改产品路由、未调参、未调用模型。P10/S3性能基线不在本轮范围。

## 1. 标签与边界说明

单标签四类，与现有工单路由接口一致，预测的是动作，不是支付或退款最终结果：

| 类别 | 判定说明 | 边界案例 |
|---|---|---|
| order_status | 明确查询订单履约、配送、物流状态 | 无订单号仍是该类，业务流程另要求补订单号；不能因缺号一律标clarify |
| return_request | 明确申请退货、换货、退款 | 只查询退款进度不等于新退款申请，无法确定时clarify；申请进入人工队列，不直接退款 |
| human | 明确要求人工，或需要人工介入的投诉、盗刷、隐私等安全事项 | 显式人工和普通业务同时出现优先human；“不要转人工”是否定，不按字面人工词命中 |
| clarify | 信息不足、否定后的意图不明、超出上述范围、无法择一的并列意图 | “不退货，只查物流”标order_status；“查物流并退货”不能判断主意图则clarify；引用别人的命令/提示注入不执行 |

标注单元包含合成顾客当前一句及必要的已知上下文，禁止把规则输出当标签。标注表保留来源、文本哈希、标签、依据码、uncertain、角色确认状态。模板扩写、否定、错别字、混合意图、缺订单号单独分层；不为凑类目均衡改标签。含糊样本优先保留clarify并记录原因；角色都无法确定的ECD候选排除，不能声称是顾客首句。

## 2. 2000条来源与ECD边界

建议正式集：ECD 1200条（60%），P2结构数据衍生的合成顾客提问800条（40%）。这只是待批配额，不是已完成分布。先对ECD按完整会话/近重复族聚合，去掉响应选择任务的重复正负配对；顾客角色须经本地人工判读确认。对不确定角色不补标签、不假定第一片段是顾客；不能拿P2原有规则代理类别当评测真值。若不足1200条合格顾客单元，先报告实际数量，请负责人决定调配，不能偷偷改成全合成。

P2合成只由结构化订单/商品/状态和独立模板生成，订单标识替换为虚构占位符，不含用户账号、邮箱、密码、记忆或真实支付字段。不能从P2的ECD导入messages/tickets文本取句来冒充纯合成。50条小样仅从该合成来源生成，不进入最终测试。

ECD目前的事实：已下载、已分词；**没有完成全面PII脱敏验证**，发送方角色未全量确认；作者仓库未发现明确数据许可，现有允许范围只按本地个人评测记录，不能解释为允许第三方API处理或公开再分发。授权状态记录为 `third_party_processing=pending_owner_confirmation`、`redistribution=not_authorized`，不能标“已获许可”。负责人确认也不能自动替代上游数据许可；若许可仍不明，建议ECD仅本地人工分析，不外发，正式配额另议。后续如获适当授权，先本地检测/替换电话、邮箱、地址、个人/账号及订单标识，人工抽检，再报告剩余风险；“脱敏”不等于取得许可。

公开仓库放标注规范、合成数据、分层计数、数据哈希和许可说明。ECD原文及可复原文本的标签包只放.local，不公开。与原方案“评测集入库”的偏差是仅发布可合法公开的部分及重建方法，不把无明确再分发许可的ECD文本入公开Git。

## 3. 一位人工标注者可执行的流程

1. 冻结规范后，DeepSeek对允许外发的数据作第一遍机器标签。ECD未批准期间不调用它；相关标签缺口必须如实保留。
2. 负责人独立标注300条分层随机子集，隐藏机器标签和产品预测。先标约50条开发候选校准规范；这一批不进入正式kappa的盲标300条。
3. **Cohen's kappa在人与DeepSeek之间计算**；同时给原始一致率、混淆矩阵、类别占比、样本数和置信区间。不是两位人类标注者的kappa，也不能写“人工双标”。二者都选择uncertain的样本不擅自排除以抬高分数，报告缺失/弃权计数与计算口径。
4. 300条分歧由负责人裁决；其余1700条机器标签是silver，不是人工真值。优先补审高风险human漏转、机器低置信度和模板异常；没有审过的不宣称人工确认。
5. 建议盲标300条按开发210/最终90分配。最终测试同时报告600条银标混合口径和其中90条人工确认子集，绝不把600条全叫人工金标。人机一致性在任何裁决之前计算；最终侧kappa延后到解封后才发布。

**避免循环论证：**同一DeepSeek既标注又作待评模型存在同源偏差。机器silver结果只能作为探索性指标，独立人工90条最终子集是较可信但样本有限的对照；不能把同源模型自我一致包装成准确率。若要更强结论，需要负责人扩大人工最终子集，或另批独立标注模型及预算，不默认增加模型费用。

## 4. 开发1400 / 最终600与隔离

按来源与近重复/模板族分组后固定随机种子分层70/30，ECD同会话族、P2同模板近重复族不得跨集；记录来源/类别分布，不承诺不可能同时满足的精确族内比例。300条盲标抽样在分割完成后进行。小样与旧47条回归集不计入正式2000条，不作最终真值。

建议由单独的封存命令读候选并输出开发集与加密最终集，开发过程只获得开发内容、最终密文与SHA256清单；最终文本、标签和解密口令不放开发配置。口令由负责人保管，通过独立终端输入，不进聊天、Git或日志。生成/人工标注最终部分时只展示给负责人，不展示给调参agent；打印统计不得包含样本。实现前需负责人选定能执行的密钥交接方式。

调参入口只接受split=dev并检查清单；cache目录按split隔离，不能读取最终预测缓存。阈值/规则/提示词/模型名/源码提交冻结并签署清单后，负责人授权解封，三个版本在同一次最终运行中评测；创建不可覆盖完成标记，之后调整只用新数据或声明新的实验。模型网络失败重试由冻结规则处理，不因看到错误样本再改规则重跑最终。

限制：同一账号有完整文件权限，普通文件名/脚本开关不能技术上保证agent绝不偷看；真正的开发期隔离依赖负责人掌握最终集解密口令，不能将程序自律说成安全隔离。负责人看过用于标注的最终样本不用于反馈规则设计。

## 5. 三个版本、调用控制与费用

- rule：冻结现有route_message为基线，开发期修改另留版本和摘要；0模型调用。
- model：拟用可配置 `deepseek-flash`，当前官方映射DeepSeek-V4.1-Flash-1017，非思考模式、temperature=0，严格四类JSON输出并校验，不接受任意工具/指令。分类提示与机器标注提示分开留摘要。
- hybrid：冻结规则命中依据/置信档，仅低置信度调用与model版本**相同**分类提示；模型失败保守clarify并记录失败，不静默把失败当正确。阈值只在开发1400条扫描，P8先实现同脚本三个版本，收益比较不提前预设。

独立接入 `src/agent_ops/deepseek.py` 不改火山方舟实现。地址 `AGENT_OPS_DEEPSEEK_ENDPOINT`、模型 `AGENT_OPS_DEEPSEEK_MODEL` 必须显式配置；沿用 `AGENT_OPS_LLM_CONCURRENCY`（默认8）和超时配置，一个评测进程共用实例/信号量。429/408/5xx及传输故障指数退避、尊重Retry-After，最多3次；记录网络请求数、重试数、限流数，整个请求含排队/退避受超时约束。禁止每条新建一个并发池。

Key已定位服务器 `/home/ubuntu/.config/llm/deepseek.env`，权限600，只含DEEPSEEK_API_KEY配置，值未展示或复制入仓库。本轮未验证Key有效性/余额/实际模型可用性。评测显式从该私有文件加载，不改变运行中的导购配置。每次成功调用在 `.local/<eval-run>/cache`（目录700，文件600）缓存输入SHA256/字符数、数据集摘要、请求/返回模型名、UTC调用时间、usage、重试次数和返回JSON。键包括模型/地址/数据集摘要/完整消息/温度等参数；相同数据与提示重跑直接用缓存，修改提示/模型显式产生新调用。失败不伪装成成功缓存。ECD默认在接入层拒绝。

**小样授权未收到前不调用任何模型。**拟先50条P2合成、一个分类提示、最多50×3=150次HTTP尝试；测实际平均输入/输出tokens、缓存命中token、成功/限流/重试/失败数及模型返回名/日期。先冻结小样计费结果再申请全量。50条质量数字不外推正式集准确率。

2000条×3版本=6000条路由判定，**不等于6000次付费调用**。规则2000次为本地；模型2000；混合最多2000个低置信候选。相同classifier调用和数据集摘要可复用model缓存：预测最多2000次独立模型请求、最坏6000次HTTP尝试；若后续批准不同提示/上下文，按4000次独立模型请求、最坏12000次尝试预算。机器标注是另一个提示，最多另2000次/6000次尝试；不能藏在路由费用里。ECD未获授权时这不是可执行的全量调用计划。

2026-10-29查阅[DeepSeek官方价目](https://api-docs.deepseek.com/quick_start/pricing/)：所选Flash每百万token，未命中输入$0.15（非高峰）/$0.30（高峰），输出$0.60/$1.20；命中输入$0.003/$0.006。为保守估算不预设供应商缓存命中，采用高峰价。令小样平均输入I、输出O，单请求期望费用为 `(0.30*I+1.20*O)/1000000` 美元；乘实际独立调用量，再单列重试上界和标注费用。小样测量前I/O和总价均**未验证**，不编造平均token或具体预计账单。温度0也不保证供应商输出绝对确定，复现依赖落盘响应和模型版本记录。

## 6. 指标与批准点

先测规则基线，再同集同口径比较macro/micro precision/recall/F1、各类混淆、human漏转率（真human却预测非human）、转人工率、模型调用比例、失败率、token/费用。同时报告数据来源、银标/人工子集和类别不均衡，不预设任何提升幅度。P8不跑缓存性能基线或S3。

等待负责人确认：四类边界、1200ECD/800合成配额及ECD是否允许第三方处理（许可未明时建议仅本地）、300条人机盲标与90条人工最终子集的限制、最终集口令保管方式、先50条小样授权。小样结果与费用经确认后才可全量。未批准前不实施数据集/三个版本/调参/全量调用。
