# P9 压测基础设施方案（待确认，不执行）

2026-10-30，Codex。仅方案和只读盘点；不启动桩/负载、不调内核或服务配置、不开放端口、不调用模型。P8已验收；最终集已经使用，P9不复用它作任何路由调参/评测。实际主机规格、服务限额快照仅放被忽略的.local/p9-planning及私有交付附件；本公开方案不记录它们。

## 1. 对象和范围

P9只建立模型桩、SSE负载程序、故障注入、JSON证据与报告工具，不提前开展P10/S1–S7优化或声称有优化收益。

区分两种负载，分别出报告，不能互换：

- **传输连接负载**：独立bench API调用现有streaming.stream_run，工作协程按固定时长保持（如600秒，且至少覆盖预热/爬坡/测量窗口加余量），形成真实HTTP/1.1 SSE流，测1k/5k/10k建立连接、健康首帧/心跳、慢读和断开。固定长工作是显式fixture，不改生产超时，不冒充真实业务完成率。
- **业务端到端负载**：复制当前API/鉴权/编排代码到隔离bench实例；用专用测试账号、独立PG/Redis数据和只读P2合成商品/库存，模型端点指向桩。测入场→等待模型槽→工具执行→SSE结束，保留当前错误码/总超时/并发限制。现有总超时和模型槽可能使流提前结束，结果如实记录；不得为了凑万连接改生产行为。认证开/关两种模式显式标注，不能把免认证fixture当线上吞吐。

**一万个SSE连接≠一万个模型并发≠一万个业务成功完成。** 网络传输、桩校准和真实业务负载分开量化。

## 2. 共机保护与运行窗口

GetAudio、GetVideo和agent-memory是保护对象，不停服务、不改它们的cgroup、数据库池或日志。不能承诺共享机器零影响：CPU配额不能隔离内核、页缓存、网卡/磁盘和全局连接追踪表；若要求严格零干扰，SUT也必须放独立测试主机。推荐负载生成器独立，SUT在获准的非高峰窗口逐级试跑；背景任务/转码/下载/其他压测忙时不运行。

所有测试进程（bench API、桩、隔离数据库、监控）归入同一个受限bench slice，**以下为待批准的实验预算，不是实机现有配置**：聚合CPUQuota上限125%（含义约1.25个逻辑CPU）、低CPUWeight、MemoryHigh 1.5GiB/MemoryMax 2GiB、MemorySwapMax 0、TasksMax 512；各子服务进一步分配，不能各拿一份总预算。FD预算计入主机总额；SUT/桩/生成器按连接公式设置自己的LimitNOFILE。若用Docker，必须验证其进程确实受上述总预算限制（cgroup父级/容器CPU与内存上限）；不能仅限制启动docker命令的shell。若用户级控制器未委派，停止，不假装隔离生效。

独立watchdog在每个阶段前做60秒背景观测；运行中每秒收集host MemAvailable/PSI、swap in/out、主机FD数、保护服务健康/错误率/轻量只读探针延迟以及测试slice memory.events/stat、cpu.stat、进程FD、事件循环延迟。没有保护服务可读指标时，不宣称其延迟受保护；先补观测设计再批准高档负载，不触发下载/转码等实际业务。

拟定硬闸：可用内存低于预留安全线（初案2GiB）、测试slice达到MemoryHigh持续5秒、OOM/健康失败即停；保护服务p95连续3个观测窗超过本次背景基线10%、CPU/IO/内存压力持续超过预设线、出现持续swap-in/out时中止。具体压力阈值在低负载基线后固定，不能看到压力结果后放宽。看门狗失败也停。新后台任务开始即停。限制是保护边界，碰到它不能称测出了应用上限。

先100连接验证观测和清理，再1k→5k→10k；每档仅在预计内存+背景预留满足准入、上一档无保护报警时升级。额定MemoryMax不足则该档标为“未执行/预算不足”，不自动扩大、不迁移或关掉别人的服务。

## 3. 万连接的FD、端口与内存

默认使用asyncio/epoll客户端，显式把连接池最大连接数配置到目标，不能使用默认100连接池或select的1024限制。SUT FD下限 `N_SSE + N_upstream + N_DB + baseline_FD + margin`；直连万SSE建议评估32768软/硬上限，前置代理若存在通常还需额外约N个上游socket，代理自己的FD/worker_connections另外计算。生成器也需至少N个socket及文件/监控余量。全机file-max/file-nr、每进程nr_open、真实服务/proc/PID/limits、父级限制都要核对；交互shell ulimit不能替代服务限制。[内核FD说明](https://docs.kernel.org/admin-guide/sysctl/fs.html)、[systemd进程限制](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html)。

`ip_local_port_range`只约束发起端自动分配的源端口；服务器接受连接不占用一份相同意义的临时端口。单源IP到同目标IP:port的一条四元组路径最多使用可用源端口数；需扣除reserved ports、其他连接和TIME_WAIT。稳态10k可能够，关闭后立即再跑三次可能耗尽；不通过盲开tcp_tw_reuse或全局扩端口解决。每轮前确认空闲源端口/连接状态恢复，或明确使用多个已授权源IP；不靠多进程“增加”同一四元组端口空间。NAT/连接跟踪限制另计。[内核网络参数](https://docs.kernel.org/networking/ip-sysctl.html)。

内存只给估算区间，容量未验证：

`M_server = M_base + N × (Python任务/请求状态 + 每连接有界队列 + socket实际缓冲) + 共享模型等待队列/DB/追踪开销`。

举例假设应用状态16–64KiB/连接、帧上限1KiB且2帧队列、socket实际占用32–128KiB/连接，10k约增加0.48–1.85GiB，还没计基础应用、桩/数据库和代理；若单帧上限64KiB，仅两帧队列上限就约1.22GiB。上述是敏感性算例，不是实测，也不是Linux缓冲默认值。tcp_rmem/wmem最大值不是每条连接预分配量，不能相乘后当实耗，也不能忽略内核socket内存。

在100/1k阶段测memory.current增量、memory.stat的sock、RSS/PSS和实际帧大小；拟合每连接增量并留至少30%余量，若不能在总预算内同时保留背景安全线，**不跑10k**。本机能否支持SUT万连接目前未验证；同机兼任生成器会增加另一侧socket/内存/CPU，不能仅看机器总内存判断“够”。

推荐优先评估已授权的临时辅助Linux主机做生成器（当前未连接/未核验资源），Mac为备选；Windows也可，但其事件循环/计时/限制不同，结果单列。负载机须先验证CPU<70%、无内存/FD/端口瓶颈和网络带宽余量，达不到才考虑新租独立负载机，需用户决定。生成器分离不能解决SUT本身内存不足；届时需独立SUT或明确降低目标。

## 4. 模型桩与真实DeepSeek校准

新增独立DeepSeek-compatible非流式chat/completions桩和bench专用适配层，保留旧火山方舟实现。模型名/端点可配置。桩输出固定、合法、可验证的路由JSON或编排JSON，二者分profile，不拿路由短回复的延迟代表较长编排回复。SSE心跳是应用流，不是模型token流；当前历史延迟样本没有TTFT/chunk间隔，不能据此声称验证了DeepSeek token-stream。

已只读盘点既有低并发成功响应的**时间/usage元数据**，不需要重新外发ECD。开发阶段可识别556份低并发分类与1164份银标完整调用延迟候选；缓存命中的本次耗时、等待应用槽、发生重试/失败的调用不混进成功profile。先核对profile、时间窗、模型别名、token长度和网络路径/代理是否一致，再选择不少于500个唯一真实调用拟合经验CDF，以固定种子按请求ID采样，保留尾部、不用固定平均sleep代替。原始响应/请求仍.local，公开仅延迟样本/分布统计；不使用已消费最终测试集的文本/标签作任何后续校准。历史选样只凭时间戳只能作为候选，未完成逐条延迟纯净性审计，不虚称已有生产规划profile。

拟合数据与校准留出数据完全分离，不在同一数据上采样再“验证像自己”。对匹配路由profile，可先用开发样本拟合；严格低并发校准另用纯P2新合成请求、并发1或2、同模型/同prompt长度区间/同连接复用/同代理路径。若编排profile无500个匹配样本，需新增不少于500个成功fit样本，再独立采集不少于500个成功验证样本；不能跨任务混配。校准强制真实网络调用，客户端缓存只作证据，不用缓存命中满足样本数；不使用P8最终题目重新请求。新增真实调用目前为0，需本方案获批并明确调用额度后才执行。建议调用总上限1200（含重试）、并发≤2、真实请求最多3尝试，先20条匹配任务小样据真实usage报费，再在批准预算内继续；不默认无限充值。预算初案2美元，仅是待批准上限，非已发生费用或保证账单。ECD不再用于新外发，Key只本地加载，不记日志。

验收预先固定：比较**客户端所见完整调用延迟**的p50/p95比值，独立样本自助95%区间须落入[0.90,1.10]，同时经验CDF最大差D≤0.10；p99仅探索性，样本不足标未验证。不是“KS不显著就等价”。区间过宽/样本不匹配也算未通过，不临时扩大误差带。先测本地桩固定HTTP开销再拟合可控sleep，比较时把该开销算在内；网络路径变化要重建profile。真实API错误概率不从只有成功样本的缓存估计。

故障profile用固定种子/请求ID确定：可配慢尾、429（合法Retry-After）、5xx、读头后断连、响应体截断、连接重置，以及定时故障窗；比例/延迟上限/起止时刻写进JSON。注入率是实验设定，不声称真实DeepSeek发生率；桩绝不代理到真实API。低并发验证每种故障确实触发客户端既有超时/重试和取消，停止负载后无孤儿任务。高并发故障实验收益留到P10/S4，不提前调入口限流/熔断策略。

## 5. 负载程序与三次波动验收

新程序支持固定并发、固定到达率、连接爬坡、保活时长、慢读比例0/10/30%、随机种子、逐连接生命周期及客户端早断。慢读必须限制/停止真实socket读取（含客户端库预读），以字节/秒和暂停时段定义；仅在消费事件回调里sleep不能证明服务端发生背压。记录实际连接数/healthy及slow数，未达到目标就标失败，不拿计划并发冒充已建立并发。

SUT/生成器/桩独立监控：TTFB、首个SSE事件、心跳间隔、成功完成率、超时/429/5xx/断连/慢消费者中止、事件循环延迟、队列/模型槽等待、RSS/PSS/cgroup内核内存、CPU、FD、网络、端口和TIME_WAIT。控制观测量/批量落盘，禁止每帧同步打印；避免追踪全采样和磁盘写把压测变成日志压测，采样率写入配置固定。若生成器本身满载，不能归因于SUT。

同一脚本、同一提交、同一profile/fixture/种子/并发/慢读比/资源预算/采样率，**连续三次完整独立运行**，不挑最好三次。每次先固定预热60秒、固定ramp、稳定窗口180秒，结束后排空连接、确认TIME_WAIT/资源/背景健康恢复，再开始下一次；休息用于恢复，不为了挑安静结果而重试。用固定请求ID序列让故障安排可重复。

波动公式预先定为 `spread=(max(x1,x2,x3)-min(x1,x2,x3))/mean(x1,x2,x3)`。对实际达到的连接数、有效吞吐、健康首帧p95/p99、完整延迟p95、峰值内存逐项要求≤10%，且三次都无保护闸报警、都达到相同负载和最低有效样本量。目标并发未达成、保护中止、生成器饱和均不可判通过。错误率另报分子分母与Wilson区间；均值为0的计数三次全0视为稳定，否则失败/不适用，不对零附近比值强算通过。三次不足以证明所有时段稳定，结论限定本窗口/本环境。若超过10%，保留原三次并归因背景/瓶颈，不自动剔除/无上限重跑；重新实验须新experiment_id并说明，不冒充原验收成功。

## 6. JSON与报告

计划新增schema版本化JSON、只读报告生成器及单元/低档集成验证。JSON分manifest、per-run和三次合并判定，含commit/source摘要、dirty、scenario/seed、目标及实际并发、profile摘要/真实样本出处、延迟分桶/分位数、错误分类、全部分子分母、保护中止原因、资源预算与观察、开始/结束时间、重复序号和波动计算。JSON用原子写、保留失败，中断也落partial状态，禁止覆盖旧run。

真实主机规格、地址、端口、命令行凭据、原始请求/返回、用户文本和机器标识只.local；公开JSON使用匿名environment_id、软件/场景参数、脱敏延迟/资源使用统计和结果，不发布实际主机配置规格。报告脚本不请求任何API，从JSON生成Markdown/图表并复核三次是否同场景；缺失/partial不补0、不写成通过。

验收顺序：离线schema/故障/统计测试→配额与看门狗小档演练→匹配profile真实/桩低并发校准→每档三次负载与清理→文档/原始脱敏JSON。未通过一项停止升级，不提前宣称万连接完成。
