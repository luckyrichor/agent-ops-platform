## 来源与解释

私有进程快照显示两个MySQL进程、浏览器预览和开发工具服务占有较多Swap。**Swap存量只反映曾换出的页面，不代表当前换页的贡献排序。**

当前活跃候选是另一个项目的一项MySQL服务（实际容器映射仅.local）：同一120秒窗口进程重大缺页增加311次，VmSwap下降2312 KiB，读取约12.73 MiB；另一个独立起止窗口的cgroup重大缺页增加325次，swap.current下降约2.53 MiB。两个窗口起止不同，不直接相加或当同一分母。该服务回读先前换出页面是有证据支持的解释，但不能把所有重大缺页都当swap-in：它也可能来自文件映射，read_bytes还包含数据库普通IO，Swap下降还可能由释放页面造成。没有逐页追踪，不宣称已精确归因全部865页。

部分PostgreSQL进程也有重大缺页/磁盘读取，VmSwap基本不变，不能据此认定它们正在换入。保护对象GetAudio/GetVideo/顾客memory在单独cgroup起止窗口中重大缺页、swap占用、OOM/OOM-kill/high/max事件均无增长；不把该短窗观察外推成全天无压力或负载下安全。

结合本次没有新换出、没有扫描/分配停顿、内存PSI很低，**本次更符合历史换出页面被逐渐回读，不支持“当前正在严重内存抖动”的结论**。但该结论只适用120秒窗口；不能解释先前10分钟内全部换出活动，也不能把有持续换入改写成前置闸已通过。
