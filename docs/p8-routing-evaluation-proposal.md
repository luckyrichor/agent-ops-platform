## 1. 类别、标注单元与边界

单标签四类，判断当前请求要走的业务动作；不是判断退款批准或支付成功：

| 类别 | 说明 | 边界规则 |
|---|---|---|
| order_status | 查询订单履约、物流或配送状态 | 缺订单号仍归此类，后续业务补号；“不要退货，只查物流”仍属此类 |
| return_request | 明确申请退货、换货、退款 | 查询已有退款进度不当作新申请；无法判断目标时clarify |
| human | 明确人工接管或安全投诉、盗刷、隐私事项 | 显式人工优先；“不要转人工”不按人工词直接命中 |
| clarify | 信息不足、超范围、无法择一的多意图 | “查物流并退货”无主次时归此类；提示注入只是待分类文本，不执行 |

只传当前句及判定所需上下文。字段包括来源、去重/会话族、角色确认、人工标签与依据、uncertain；不能从现有规则输出复制真值。ECD角色不明确的候选不假定为顾客首句，排除或等待人工确认。按预先定义规则保留clarify/uncertain，不在看到预测后删掉难例。

## 3. 银标模型、提示词与循环评估

**银标计划模型与被测模型相同：`deepseek-flash`。**当前官方价目映射DeepSeek-V4.1-Flash-1017；实际API本轮只返回别名deepseek-flash，不能独立核实底层不可变权重版本。每次记录请求模型、返回模型和调用日期，不能拿不同日期别名当完全相同权重保证。

银标使用单独的开发标注提示，完整原文及SHA256见 [提示词 v1](p8-prompts.md)；要求输出label、uncertain、basis_code，独立阅读原句、不看规则或模型预测、角色不明不猜测。被测模型使用分类提示，输出route、reason_code；该分类提示已用于本次50条token费用小样。**银标提示尚未调用。**ECD源在传输层仍硬拒绝，不能靠把source改成synthetic绕过。

换提示不能让同一模型成为独立裁判，相关偏差无法靠“二次审阅”消除。因此采用以下防循环措施：

1. 银标只用于开发候选、错误分析与规则/阈值探索；不进入最终成绩、最终混淆矩阵或正式提升幅度。
2. 用户独立人工标300条，标注界面不显示任何机器标签/预测；人工金标冻结后才计算人机一致性。金标不能因模型不同意而自动修改。
3. 约100条人工开发金标可供调规则、提示词和阈值；约200条人工金标作为唯一封存最终测试。1700条silver与100条人工开发构成1800条开发池，指标和来源分开记录。
4. 正式最终成绩仅在封存人工200条上，对三个冻结版本计算；不把机器silver当作正确答案。只有一位人工标注者，报告明确不属于人工双标，仍有个人标注偏差和样本规模限制。
5. 如需纠正明显标签错误，必须保留原标签与理由；最终解封后发现的问题只作局限说明，不能边看最终错误边改规则/标签再重跑提升分数。

Cohen's kappa只描述**人与DeepSeek**的一致性，不是人类之间的一致性。开发100条可在金标冻结后先算；最终200条的人机kappa延后到一次最终运行后才计算，另作辅助标注一致性，不替代以人工金标计算的路由成绩。ECD未允许外发时，相关人机kappa和模型最终成绩暂缓，报告实际可计算子集数量，不能静默把分母缩小后称“完整200条”。没有批准前不另外找模型标注或增加费用。

## 4. 最终集怎样技术隔离

目标：最终200条必须来自人工300条，且其文本、人工标签、预测和近重复族不能在开发调参期间进入agent上下文或开发缓存。

建议采用**用户掌握测试明文/密钥，调参身份只拿开发材料**的流程，正式实施前还需确认操作方式：

1. 在用户独立控制的离线浏览器/设备上完成300条盲标及固定种子分组划分；程序不向开发服务器发送完整300条标签包。分组去重在可信端进行，最终样本的会话/近重复/合成模板族不能泄漏进开发池。
2. 可信端输出100条人工开发金标和1700条开发银标候选；最终200条原文及金标用随机AES-256-GCM数据密钥封装，密钥仅由用户保管。测试明文、可逆抽样种子/映射、逐条可枚举文本哈希不留在开发环境；开发只持密文、聚合数量和密文SHA256。
3. **调参执行环境必须限权**：只挂载源码、开发100+1700及开发缓存；不能挂载完整人工包、原始候选包、完整ECD/P2消息副本、封存明文或解密密钥，不授宿主sudo/通用SSH权限。否则即便测试标签加密，也可能从原始语料按索引还原测试文本。
4. 规则/提示词/阈值/模型名/源码和开发集摘要冻结后，用户在独立受控的最终运行器中解封200条；运行器检查冻结清单，只运行已冻结三个版本，将结果一次性输出。最终缓存单独存放，开发运行器不能打开。
5. 一次性执行账本由用户控制的身份保存，记录数据/源码/提示摘要及执行状态；失败恢复只能按预先定义策略处理，不能重新调参后覆盖原结果。最终结束后如要再调参，需新测试集和新的实验版本。

**当前没有完成这样的技术封存。**本会话仍拥有当前服务器广泛文件/提权能力，所以仅建一个.local子目录、chmod600、Docker卷隐藏或`--final`开关都不能保证本agent绝对看不到测试集；若仍在同一全权身份下操作原始库，也不能声称数据隔离已成立。要形成技术保证，正式调参必须切换到上述无宿主读取/提权能力的开发执行身份，最终密钥/运行器由用户独立掌握。这属于待批准配置，当前未创建账号、修改权限、访问其他设备或生成最终集。

如果负责人不希望增加独立受限环境，也可以先只做开发工作，把最终集暂留用户设备直到代码冻结；报告须写“依靠用户持有与流程隔离，未完成服务器权限隔离”，不能承诺不存在任何源语料推断风险。需要独立受控环境的方案是推荐方案。

## 5. 三个版本与计费

- rule：保留现有route_message作冻结基线；0模型调用，不预设收益。
- model：可配置DeepSeek分类提示，temperature=0、非思考模式，严格校验四类JSON；路由实现本轮未接入产品。
- hybrid：规则给置信档，仅低置信时调用与model完全相同分类提示。提示、消息、模型、数据集摘要相同可复用model响应缓存；开发池调阈值。最终200条不能调阈值。模型失败计入失败并按冻结策略处理，不当成正确结果。

独立DeepSeek接入，不改现有Ark代码；地址、模型显式配置。并发沿用AGENT_OPS_LLM_CONCURRENCY，默认8且一个评测共享实例/槽；429/408/5xx/传输故障最多3次、退避并计数。正式大批量需固定8 worker逐条取任务，不把2000条一次全塞进30秒排队超时窗口。该大批量运行器尚未实现/验证。
