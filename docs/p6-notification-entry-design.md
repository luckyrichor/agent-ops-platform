# P6 长期通知入口方案（待用户确认，尚未实施）

拟沿用独立 TCP 18080 + 独立 Nginx 实例，只监听 IPv4，反代到回环通知处理器。现有系统 Nginx 80/443/8443、Mihomo 和客户页/API 不改动。18080 当前关闭，云规则用户已确认删除；获确认后才重新配置、开放及部署。对外 URL 只在私有 .local 构造，文档使用 SERVER_PUBLIC_IP 占位。

仅精确 POST /payments/notify 可达；其他路径404，其他方法405，不重定向、不开放支付创建、后台、健康检查或前端。只接受 application/x-www-form-urlencoded，拒绝重复关键参数和不支持的编码；不信任客户端 X-Forwarded-For。代理覆盖来源头，应用只信任回环代理。

请求体上限64KiB；请求头10秒、请求体15秒、上游连接3秒、上游响应10秒；每来源IP暂定5请求/秒、burst20，单IP同时连接10。超限429不返回success，支付宝可重试；这些是初始保护值，尚未容量验证，共享出口可能误伤，需观察后调整。持久化成功才回复success，异常/校验失败不确认；探针已删除的“收包即success”行为不得复用。

代理关闭默认access log；专用结构日志仅记录UTC时间、固定路径、方法、状态、大小、耗时、trace_id，不记录服务器公网IP、原始来源IP、query string、完整URI、请求/响应体、签名、Cookie、Authorization或私钥。需要来源聚合时使用应用层带私有盐哈希；日志写忽略的.local、600、轮转。业务审计只存脱敏原因码与内部业务关联，禁止把通知全文/完整请求参数写进报错。代理错误日志也必须避免默认输出server/client/request/upstream等地址字段：关闭默认error_log，将服务存活/退出与脱敏错误指标单独监控。此取舍会降低原始网络排障细节。

传输风险：无域名HTTP没有保密性，验签只能保护可验证内容的真实性/完整性，不提供加密；公网端口会被扫描。当前沙箱允许此路径只证明本次沙箱可行，不能当作生产支付部署方案。生产若需要TLS，须另定可信证书和入口；本轮不擅自改80/443或绑域名。云侧优先核实官方通知来源范围；未核实不编造白名单，若必须全IPv4开放则只开18080及上述唯一处理路径。IPv6入口不开放。

出站只读实测：Mihomo rule模式，TUN/auto-route/auto-redirect/strict-route开启；网关解析地址系统路由经过mihomo-tx。读取私有网关，仅进行TLS握手和普通GET /，验证系统CA证书，不调用支付API；控制器中对应连接规则类型RuleSet，实际出口DIRECT。因此该次连接经Mihomo分类但没有经远端代理节点。不代表未来规则不变，也不代表所有进程都直连。当前进程有显式HTTP(S)/ALL代理环境变量。实现建议httpx trust_env=False，显式禁用环境代理、保持TLS校验和有限超时；它只能绕过环境变量，不能绕过TUN，仍受Mihomo规则/可用性影响。本轮不修改Mihomo或出站路由。

实现顺序（确认后）：从我们库里的待支付订单读取金额/订单号，生成唯一商户单号及沙箱链接；回调用.local/alipay/alipay_public_key.txt内支付宝公钥做RSA2验签；与私有配置app_id和seller_id、库内订单及金额逐项核对；事务内状态机与持久唯一键去重，重复/乱序不得二次扣库存/重复入账。验证失败仅脱敏审计。通知或补偿查询才改变支付状态，不信前端跳转。退款需客服批准、唯一退款单号、按库内可退金额核对，处理远端超时后的查询补偿；对账读取沙箱支付/退款账单而非只比本地表。S2正确性在P6实现，正式性能优化实验仍留P10。

需补充私有配置：.local/alipay/seller_id.txt，填沙箱卖家UID（600），不能从待验通知自证商户身份；不要把它贴群。现有四文件继续原路径，仅内存转换原始密钥，不提交凭据。
