# S3 访问分布正式复核协议（2026-11-04 北京时间冻结并执行；当前勘误版）

状态：本轮按本协议执行；在 Codex 确认前不写“全部通过/可正式实验”。

## 0. 目的与边界

- 目的：对 S3 合成访问分布（Zipf 类生成器）与真实公开源 UserBehavior pv 的 LRU
  命中率一致性做一次正式复核，替代阶段1的 200k 样本探索（阶段1结果保留但口径作废，
  见 §8）。
- 数据源：`.local/datasets/raw/UserBehavior.csv.zip`（无 header，manifest
  `.local/datasets/userbehavior-v1/verified-fit-v2.json`，archive_sha256=
  ce56e7bccfe48f9c58134b691fb49430a3262fbd808a6b49f07a8c66aacc73d5）。
- 冻结拟合：item_popularity_pv，支持 N=4,068,790，zipf_exponent=0.7831831153078841
  （全源 MLE，fit_method 见 manifest）。
- 本项目 S3 合成 catalog 实际规模 = 200,000（与真实源支持集 4.07M 不同）。

## 1. 禁止的口径（相对阶段1的修正）

1. 禁止用“样本 distinct 数”定义 catalog/support：那会把 Zipf 支持集缩小到样本窗口，
   引入假热度。本协议 support 一律用各自目录规模（真实=4,068,790 的比例容量；
   合成=200,000）。
2. 禁止数值 ID 交集/“映射损失96%”类指标：真实 item id 与合成 1..200000 之间
   **不存在语义映射**，数值交集没有语义意义，不计算、不报告。
3. 禁止在看过验证窗口结果后继续调参。
4. 禁止把本协议结果说成“完全独立于源的统计泛化”（见 §7 局限）。

## 2. 采样与窗口

- 读取 ZIP 内 UserBehavior.csv **文件顺序前 1,000,000 条 pv**（无 header，首行保留；
  逐行结构校验：5 字段、behavior∈{pv,buy,cart,fav}、item/ts 可解析；非 pv 跳过并计数）。
- 前 500,000 pv = 校准窗口；后 500,000 pv = 验证窗口。文件顺序非全局时间顺序（见 §7）。
- 每个窗口独立冷启动 LRU；窗口内前 100,000 条仅 warmup（写缓存不计命中），
  余 400,000 条测量命中。

## 3. 容量定义

- 真实侧：真实完整 catalog 4,068,790 的 1% / 10% = **40,687 / 406,879**（key=真实 item id）。
- 合成侧：实际 S3 catalog 200,000 的 1% / 10% = **2,000 / 20,000**（key=rank 1..200000）。
- 这是“各自目录同百分比”比较；两目录规模不同（4.07M vs 200k）是明确限制，
  不得宣称同绝对容量对比。

## 4. 生成器

- 阶段 A（校准对照）：冻结旧指数 a=0.7831831153078841、纯 Zipf（w=1.0）、
  support=200,000，seed=20261103，在**校准窗口**与真实对比。
- 阶段 B（仅当 A 校准不过）：Zipf+uniform 混合生成器——以概率 w 抽
  Zipf(a, support=200,000)，以概率 1-w 均匀抽 rank。
  - 仅用校准窗口（前 500k pv 的测量段）拟合参数；
  - 固定粗网格 exponent a∈{0.60,0.65,...,1.10}（11 值）、w∈{0.5,0.75,1.0}，seed=20261103；
  - 目标：两档 |gap| 的最大值最小；平局按参数字典序（a,w）取小；
  - 允许一次**预声明**局部细网格：a∈a*±0.025（步长 0.0125）、w∈{w*-0.125, w*, w*+0.125}，
    截断到合法域 a∈[0.6,1.1]、w∈[0.5,1.0]；只看校准，评估后即冻结，不得再看验证。
- 阶段 C（验证）：选定参数与协议 hash 先写入不可覆盖冻结文件
  （`.local/s3/distribution-freeze-v1.json`，O_EXCL，已存在则中止），
  之后才允许跑验证窗口：3 个合成 seed=20261104/20261105/20261106，各 500,000 事件
  （前 100k warmup、余 400k 测量），逐 seed 与真实验证窗口对比。
  **通过判据：3 个 seed 的 1% 与 10% 两档 |gap| 全部 ≤5pp**（任一 seed 任一档 >5pp 即失败）。
  失败结果保留原样，不改门槛、不伪造通过、不进行新一轮看验证调参；失败时写出
  下一步选项交 Codex 决策。
- 诊断（可选，不替代主闸）：support=真实完整 4,068,790 的同支持集对照，仅作参考。
  **它通过不能替代 support=200,000 的主闸。**

## 5. LRU 与实现要求

- 标准 LRU：命中 move-to-end；未命中淘汰队首；命中率=测量段命中/测量段请求数。
- CDF 用 array/bisect 预构建一次，逐请求二分抽样；不在循环内重建全 CDF。
- 调参过程输出进度（每组合 objective）。
- 资源上限：1 CPU / 1GiB（systemd scope）；主机 MemAvailable<2GiB 或 OOM 增长即中止；
  总计算预算 15 分钟（不含模型调用；业务负载不调用模型），超预算保留进度报告、不得假完成。

## 6. 输出与隐私

- 公开输出：仅聚合统计（命中率、gap、参数、seed）+ 输入/输出文件 SHA256；
  原始真实请求序列、逐请求采样只写 `.local/s3/` 私有文件，不导出真实用户/请求原文。
- 公开报告不得含 DSN/secret/真实源序列。

## 7. 局限（必须在公开报告中原样携带）

1. 旧指数来源于**历史全源拟合**（旧 MLE 已看过全源），新混合参数只用本次校准窗口选择；
   本协议只保证“本轮新增调参不看验证窗口”，不能称完全独立于源的统计泛化。
2. UserBehavior 文件顺序不是全局时间顺序：不声称生产实时访问仿真；
   校准/验证窗口是文件顺序切分，不是时间切分。
3. 真实/合成目录规模不同（4.07M vs 200k），容量为同百分比不同绝对值。
4. 阶段1的 200k 样本结果仅探索性质，口径已被本协议替代（作废口径，原始文件保留）。
