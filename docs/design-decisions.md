# 设计取舍

最后更新：2026-10-18；Codex；本次代码基线 agent-ops-platform@53508fe + 本轮修改。各历史章节保留原始来源。

M1 先用确定性 planner + 四角色 handler，隔离编排正确性与模型随机性。用户可以观察实际任务依赖、分派与汇总；更换 planner/工具不必重写 DAG executor。代价是没有自由自然语言解析，用户需显式提供预算/类目/地域。真实模型/工具接入后必须另外评估，当前不夸大。

DAG 执行按 ready wave 并发：catalog 后 pricing/shipping 独立，recommendation 依赖二者。plan 在执行前检查 duplicate/unknown/self/cycle，避免挂起；每角色超时，失败不伪造成功，下游 blocked 且独立结果保留。任务异常文本可能有工具正文或凭据，所以只返回固定 error_code。

调用者取消传递到 gather/wait_for 子任务；未做 SSE 背压或高并发压测，取消基础测试不是 M3 的替代。M1 不依赖 memory 可用性，M2 再通过 HTTP SDK 接入，绝不直连它的数据库。
## 2026-10-02 记忆工具与流式取舍

用官方HTTP SDK而非直接访问memory数据库，转发调用者身份而非共享租户凭据。稳定run_id只保证记忆写幂等；409冲突显式传播，不静默制造新key。历史偏好只能收紧当前预算。每请求容量2队列和入队超时让慢消费者局部取消；关闭生成器必须join producer与工具任务，实际HTTP断开测试验证取消链。流的是运行状态，不声称LLM token或完整trace。见memory-streaming.md。此前章节为历史记录。

## 2026-10-08：失败树、取消和终止通知

未执行的 blocked 任务仍生成 agent span，记录 task_id 与直接 blocked_by，不生成伪造的 tool span。阻塞节点不单独标 ERROR，实际失败工具及业务请求才标 ERROR，避免把一次依赖失败计成多个执行故障。

CancelledError / GeneratorExit 记录 cancelled 与稳定原因码，并继续传播、等待子任务收尾，不记录异常事件或设置 ERROR。HTTP 使用纯 ASGI 中间件保持 context 跨完整响应周期，增加 commerce.http 外层 span；成功体、业务错误体、SSE started/error/aborted/result 与 X-Trace-Id 头关联同一 trace。响应开始后无法修改 HTTP 状态，SSE 用终止事件报告。

终止事件使用队列之外的单个槽位，保证容量 2 的队列堵塞时也能记录 aborted/SLOW_CONSUMER 并及时取消工作，不再等待向满队列入队。消费者恢复读取后先读完最多两条排队帧，再读终止帧；已断开的连接无法保证通知送达。队列超时与业务 TimeoutError 区分，后者属于 RUN_FAILED。未改变模型、安装软件或启动常驻服务。

模型权限说明：此前 mini 未开通为历史记录；截至 caa453f，mini 与 2.1-lite 都已完成真实调用 3/3 初验，默认仍为 2.1-lite。

## P3：认证与权限（2026-10-23，Claude Code）

范围按方案第六节 P3 与附录 B1/B6：邮箱密码登录、customer/agent/admin 三角色、取代共享人工令牌和无鉴权工单查询。P4 的队列/抢单/租约/推送/统计、P5 前端、P6 支付、P12 登录限流都没做。接口清单与兼容性变化见 [docs/auth.md](auth.md)。

**令牌机制：短期 JWT 访问令牌 + 不透明可轮换刷新令牌。**

- 访问令牌：HS256 JWT，**15 分钟**，含 sub（账号 id）、role、cid（顾客对应的 commerce.users id）、sid（登录会话 id）、iss/aud/typ。校验只验签名和声明，**不查库**：每个请求省一次数据库往返，多 worker 共用同一签名密钥即可。
- 刷新令牌：256 位随机串，库里**只存 SHA-256 摘要**。**7 天**有效，每次刷新都换新（旧的标记已用），同一次登录形成一个 family，**最长 30 天**，轮换也不能延长。已用过的刷新令牌再出现，就当作被盗：整个 family 吊销（OAuth 2.0 Security BCP 的 refresh token rotation 做法）。
- 退出：吊销当前 sid 对应的 family。管理员停用账号：吊销该账号全部刷新令牌，登录也被拒。

**代价（必须讲得清）：** 访问令牌无状态，所以退出、停用、改角色后，已发出的访问令牌**最多还能用 15 分钟**。15 分钟是这个窗口和刷新频率之间的折中。同一刷新令牌被并发提交时（例如前端两个标签页同时刷新），只有一个成功，其余被当成重放、整个 family 被吊销，用户需要重新登录。严格但安全；如果 P5 前端经常触发，再加几秒宽限窗口。

**没选的方案：**

| 方案 | 为什么没选 |
| --- | --- |
| 不透明会话令牌，每个请求查库/Redis | 能立即吊销，但每个请求多一次存储往返，S1/S3/S6 压测会把它算进去；P3 没有立即吊销的硬需求。将来要做，可以在 JWT 上只加一次 sid 黑名单查询，不用推翻现在的方案。 |
| 只有长期 JWT、没有刷新令牌 | 要么有效期长（泄露风险大），要么频繁重新登录；也没法吊销。 |
| RS256/EdDSA 非对称签名 | 适合多个独立服务各自验签。现在只有一个业务进程签发和验证，对称密钥更简单；agent-memory 用它自己的令牌，不验我们的 JWT。拆服务时再换。 |
| 刷新令牌放 HttpOnly Cookie | 能防 XSS 读取，但要处理 CSRF 和跨域。没有前端前定不了，P3 先用 JSON 请求体，由 P5 决定。 |

**密码：** argon2id（argon2-cffi 默认参数，RFC 9106 低内存档：t=3、m=64 MiB、p=4）。每次哈希 64 MiB，7.5 GiB 机器上用信号量限制最多 4 个并发哈希，并放到线程里跑，不堵事件循环。邮箱不存在时也对一个假哈希做一次验证，让响应耗时不暴露邮箱是否注册；邮箱不存在、密码错、账号停用、邮箱格式错，统一返回 401 INVALID_CREDENTIALS。数据库 CHECK 要求 password_hash 以 `$argon2id$` 开头，明文写不进去。密码字段 max_length=256，防止超长请求体耗光 argon2 的 CPU；422 响应沿用既有规则，不回显 input。

**账号表与 100 万占位用户分开：** 方案第 4 节把 email/password_hash 列在 users 表里。实际做法是另建 `auth.accounts`，顾客账号用唯一外键 `customer_user_id` 关联一个 `commerce.users`。P2 的 100 万行仍然只是数据标识，没有凭据；只有演示脚本显式关联的几个可以登录。CHECK 保证 customer 有且只有一个关联，agent/admin 没有关联。

**权限判定放在 HTTP 边界：** 角色由路由依赖判断（401 未登录 / 403 角色不符）。归属用 SQL 条件 `user_id = 令牌里的 cid` 过滤；别人的订单、会话、工单返回 **404 而不是 403**，不暴露资源是否存在。下单请求体不接受 user_id，归属只来自令牌。客服能读所有工单、能处理工单（B1）；但 /orders 和 /support 的会话接口只给顾客，客服调用一律 403。客服按工单查看关联订单的面板属于 P4 工作台。

**幂等键按顾客隔离：** 原来 support 幂等键的作用域是全局，请求摘要里没有用户。不同顾客用相同的 key 和正文，会拿到别人工单的快照，这是越权。现在 scope 改为 `support.request:<cid>`。commerce 下单的摘要里本来就有 user_id，跨用户撞 key 只会 409、不会回放，所以没改。

**内存基线开关：** memory 模式配内存账号库。没给签名密钥时，每个进程启动随机生成一个，重启后令牌全部失效，和内存工单的生命周期一致。postgres 模式没有 `AGENT_OPS_AUTH_SECRET`（不少于 32 字节）就拒绝启动，不会悄悄用临时密钥。


## 2026-10-26 P3 收尾边界（Codex）

平台 JWT 仅供平台 API 使用。核对固定 agent-memory SDK 与现源码，租户/用户只来自 RS256 UUID JWT，没有服务身份加平台 bigint 用户标识协议；不共享密钥、不转发平台令牌、不造 UUID 映射假装完成隔离。按负责人批准的后备策略，HTTP 导购登录后不调用记忆，明确 not_configured，P7 前另行确定双方协议，改接口先汇报。

历史种子只通过关联会话且全部会话用户一致时填归属，不依据订单号、文本或轮转次序猜测；无归属顾客不可见、staff/admin 可读。主库测试工单不回填。P3 不给客服开放订单；P4 仅在工单详情查看该工单关联订单，每次审计。

基准默认预先登录、签名检查计入单次请求；关闭认证仅显式基准工厂，正常入口不读开关。保留旧标签和旧结果；新测量独立标记，不用异日期旧数字推出认证成本。本轮只验脚本合约，不做优化结论。证据见 reports/p3-followup-2026-10-26/delivery.md。
